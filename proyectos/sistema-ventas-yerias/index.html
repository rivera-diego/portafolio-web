01 / contexto

Un sistema de negocio visto desde tres superficies

Ferretería Yerias representa un escenario empresarial con operaciones conectadas: productos y categorías, proveedores, compras, inventario, ventas, comprobantes y usuarios. El reto era llevar la misma información de negocio a una interfaz web y a un punto de venta de escritorio.

3repositorios del ecosistema
2clientes: web y escritorio
1modelo relacional en SQL Server

Usuarios y alcance

El sistema está orientado a personal de ventas, almacén, administración y usuarios con distintos roles. El cliente web facilita la gestión y los reportes; la aplicación Windows Forms concentra el flujo de punto de venta y operaciones locales.

02 / solución

Módulos que reflejan el flujo comercial

Catálogo e inventario

Productos, categorías, marcas, proveedores y control de stock para mantener la operación organizada.

Compras y ventas

Registro de compras, carrito/punto de venta y emisión de comprobantes con detalle de líneas.

Usuarios y roles

Autenticación y autorización para separar responsabilidades dentro de la solución empresarial.

Reportes

Consultas y reportes de ventas, incluido filtrado por rango de fechas en la aplicación de escritorio.

03 / arquitectura

Integración web y desktop alrededor del dominio

El ecosistema contiene una API .NET para el cliente React y una aplicación WinForms que trabaja con Entity Framework y SQL Server. Esta diferencia de integración es importante: no se presenta la aplicación de escritorio como si fuera simplemente otro frontend HTTP.

04 / decisiones

Decisiones y aprendizajes de integración

  • Separar API y cliente web permite aplicar una arquitectura cliente-servidor con documentación Swagger.
  • El modelo de entidades y migraciones facilita representar operaciones comerciales relacionadas y reportables.
  • La aplicación de escritorio resuelve el escenario de punto de venta local, donde la experiencia operativa es distinta a la del panel web.
  • El caso evidencia el costo de mantener lógica acoplada a interfaces distintas y sirve como base para una futura separación de dominio y servicios.

Mi participación

Construí y conecté las piezas del ecosistema de ventas, trabajando el backend, el cliente web y la aplicación de escritorio como partes de una misma solución de negocio.

05 / workflow

IA aplicada sin ocultar el trabajo de diseño

La IA se utilizó como apoyo para comprender requisitos, explorar componentes, resolver errores y acelerar documentación. La lógica de negocio, el modelado de entidades, la integración de clientes y la validación de los flujos requirieron revisión técnica y pruebas propias.

Traducción de negocio

El trabajo parte de operaciones concretas —comprar, vender, controlar stock y reportar— antes de elegir la interfaz.

Estado de la evidencia

No atribuyo a este repositorio un prompt público específico ni porcentajes de código generado; la comunicación se mantiene en el nivel de workflow asistido.

06 / evidencia

Evidencia para conocer el sistema

  • La API documenta endpoints, entidades, seguridad JWT y acceso Swagger.
  • El cliente web contiene módulos de catálogo, ventas, compras, usuarios y reportes.
  • El repositorio de escritorio contiene formularios de login, productos, ventas, búsquedas y reportes.
  • No existe actualmente una demo pública desplegada; la evidencia visual recomendada es una captura del dashboard, el flujo POS, un reporte y el diagrama de arquitectura.
  • El sistema debe ejecutarse en un entorno local con SQL Server y las herramientas .NET correspondientes.
07 / roadmap

Hacia un sistema más fácil de desplegar

La siguiente mejora sería extraer la lógica de dominio a servicios desacoplados, agregar pruebas automatizadas, actualizar la API a una versión moderna de .NET y preparar una demo controlada con datos ficticios para mostrar el producto sin depender de un SQL Server local.
